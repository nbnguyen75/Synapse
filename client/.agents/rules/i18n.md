# Internationalization (i18n) Rules — ARIA Desktop

1. **No Hardcoded Strings**: Every user-facing string (labels, titles, placeholders, descriptions, buttons, tooltips, confirmations, error messages, toast notifications, Zod validation errors) must be managed through Paraglide messages in `messages/en.json` and `messages/vi.json`.
2. **English First & Complete Translations**: All message definitions and default text must be authored in English first (`messages/en.json`), accompanied by an accurate Vietnamese translation in `messages/vi.json`. NEVER mix English and Vietnamese within the same string, label, or view (no hybrid Vietnamese-English text).
3. **Agent Documentation Language**: All agent rules, skills, internal documentation, comments, and project documentation (`AGENTS.md`, `.agents/rules/*`, `.agents/skills/*`, `docs/*`) MUST ALWAYS BE WRITTEN IN ENGLISH.
4. **Import Syntax**: Always import messages specifically as:
   ```typescript
   import { m } from '@/paraglide/messages';
   ```
5. **Usage**: Call the message function: `m.some_message_key()` or pass parameters `m.some_message_key({ name: 'ARIA' })`.
6. **Zod Validation Integration**: Always import Zod as `import { z } from 'zod/v4';` and provide error messages using Paraglide messages, e.g.:
   ```typescript
   export const noteFormSchema = z.object({
     content: z.string().trim().min(1, m.notes_content_required_warning()),
   });
   ```
7. **Key Naming Convention**: Use lowercase snake_case prefixed by domain or feature (e.g. `header_create_new`, `settings_appearance_title`, `notes_content_required_warning`).
8. **Consistency & Compilation**: Whenever a new message key is added, define it in both `messages/en.json` and `messages/vi.json`, then compile via `bun --bun gen:paraglide`.
