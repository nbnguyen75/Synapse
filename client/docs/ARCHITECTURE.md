# Synapse Web — Architecture

## Model

**Feature-Driven Architecture (Vertical Slices).** Everything needed for one
feature — API calls, components, hooks, store, types, utils — lives together
in one folder. If there's a bug in a feature, open that feature's folder and
the whole logic is there.

## Directory Structure

```text
src/
├── assets/                  # Images, icons, static fonts, global styles
├── components/
│   ├── ui/                  # Unmodified shadcn/ui primitives (Button, Dialog, Input...)
│   └── common/               # Shared reusable components (Header, Footer, LoadingSpinner...)
├── config/                  # App constants, env variables, site metadata
├── features/                 # 🧠 Core of the app — one folder per business domain
│   ├── auth/
│   │   ├── api/              # API calls (tanstack query endpoints)
│   │   ├── components/       # LoginForm, RegisterForm, OTPInput...
│   │   ├── hooks/             # useLogin, useRegister...
│   │   ├── store/             # useAuthStore.ts (Zustand)
│   │   ├── types/
│   │   └── utils/
│   ├── notes/
│   └── ai-chat/
├── hooks/                    # App-wide custom hooks (useDebounce, useMediaQuery...)
├── lib/                      # Third-party lib config (query client, api client, utils.ts...)
├── providers/                 # Global providers (ThemeProvider, QueryProvider, ToastProvider...)
├── routes/                    # 🚦 TanStack Router file-based routes (kept THIN)
│   ├── __root.tsx
│   ├── _auth.tsx
│   ├── _auth/
│   │   ├── login.tsx
│   │   └── register.tsx
│   ├── _authenticated.tsx     # Auth guard layout
│   ├── _authenticated/
│   │   ├── dashboard.tsx
│   │   └── profile.tsx
│   └── index.tsx
├── store/                     # Global Zustand stores (useThemeStore, useSidebarStore...)
```

Outside `src/`:

```text
messages/                # Translation source files (en.json, vi.json)
project.inlang/          # Paraglide/Inlang project config
```

## Key Architectural Rules

### 1. Thin routes

`routes/**` files only wire up the route: params, auth guard, and rendering a
component from `features/`. No business logic or heavy JSX in route files.

```tsx
// routes/_authenticated/dashboard.tsx
import { createFileRoute } from '@tanstack/react-router';
import { DashboardPage } from '@/features/dashboard/components/DashboardPage';

export const Route = createFileRoute('/_authenticated/dashboard')({
  component: DashboardPage,
});
```

### 2. Auth guard

- **State** lives in `features/auth/store/useAuthStore.ts` (Zustand).
- **Guard** lives in `routes/_authenticated.tsx` using TanStack Router's
  `beforeLoad`, redirecting to `/login` with a `redirect` search param if
  unauthenticated.

### 3. shadcn/ui boundary

Anything generated by `npx shadcn@latest add ...` stays untouched in
`src/components/ui/` — pure primitives, no business logic. Compose them into
feature-specific components inside `features/<name>/components/`.

### 4. Rule of Three

Don't pre-emptively move things to `components/common/` or `hooks/`. A
component/hook/util starts inside its feature folder. Promote it to shared
space only once a **third** feature needs it.

### 5. Path aliases

Always import via `@/...`, never relative chains like `../../../../components/ui/button`.

### 6. Feature deletion = clean deletion

Deleting a feature means deleting `src/features/<name>/`, its route files, and
its translation keys (see i18n below). No orphaned code should remain elsewhere.

## Backend Integration

- All API calls go through the **Kong gateway** (single base URL), not directly
  to individual services.
- JWT is attached to requests after login; Kong verifies it at the gateway.
- Backend services the client integrates with: Auth (Bun/Hono), Notes (Spring
  Boot), AI (Node/Hono, RAG + agentic tool calls). These are out of scope for
  this repo but define the API contracts the client consumes.

## i18n (Paraglide-JS)

- Compiler-based, not runtime-JSON-based: only used translation strings are
  bundled (tree-shaken), and `m.` gives full autocomplete/type-safety.
- Source files: `messages/en.json`, `messages/vi.json`.
- Generated output: `src/paraglide/` — **auto-generated, never hand-edited**.
- Key naming convention: `[feature]_[component]_[element]`, e.g.
  `auth_login_title`, `notes_list_empty_state`, `ai_chat_send_button`.
- When deleting a feature, also remove its `[feature]_*` keys from both
  `messages/en.json` and `messages/vi.json`.
- Usage in components: import `* as m from '@/paraglide/messages'` and call
  `m.some_key()` directly — no `useTranslation()` hook needed.

## Dark Mode

Implemented per shadcn's official Vite integration guide
(https://ui.shadcn.com/docs/dark-mode/vite). The theme provider lives in
`src/providers/` (e.g. `theme-provider.tsx`) and wraps the app in `main.tsx` or
`__root.tsx`. Theme toggling uses `next-themes` (already installed).

## Theming — Color Tokens

Any color value added or modified in the shadcn theme config (CSS variables in
`index.css` or `components.json`-driven theme files) must be expressed in
**OKLCH**, not hex/rgb/hsl. This applies to both light and dark mode token sets.

## Component Library Boundary

- `src/components/ui/` — shadcn/ui primitives only, generated via CLI, never
  hand-modified for business logic (existing rule, unchanged).
- Aceternity UI components, once added, live in `src/components/ui/` alongside
  shadcn primitives if they're generic/reusable, or inside a feature's
  `components/` folder if feature-specific (e.g. a landing-page hero animation
  used only in one place stays in that feature).

## AI-Related UI

Any component rendering AI output, streaming responses, or AI tool-call state
(e.g. the AI chat feature) is built with **AI SDK Elements** as the base layer,
composed with `streamdown`/`react-markdown` for content rendering inside those
elements. These live in `src/features/ai-chat/components/`.

## Data Fetching Pattern

All data fetching flows through **TanStack Query**, with **better-fetch** as
the underlying typed HTTP client (paired with `zod` schemas for response
validation where relevant). Feature-level fetch logic lives in
`src/features/<name>/api/`, exposing typed query/mutation hooks — components
never call `better-fetch` or TanStack Query directly inline.
